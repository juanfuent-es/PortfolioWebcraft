Objetivo

Transformar un conjunto de contenidos en un sistema organizado, comprensible y escalable mediante principios de estructura, jerarquía y organización de información.

Temas

Agrupación

Objetivo: Reunir contenidos con características o propósitos similares.

Descripción: Después de construir el universo de información y realizar una selección consciente del trabajo, es posible comenzar a establecer relaciones entre los contenidos. Agrupar consiste en reunir elementos a partir de características compartidas sin necesidad de definir todavía una estructura definitiva.

Los mismos proyectos pueden agruparse de diferentes maneras: por disciplina, técnica, tema, año, cliente, contexto, formato o cualquier otra característica relevante. Cada criterio produce una lectura diferente del mismo conjunto de información.

La agrupación permite reducir la complejidad del universo inicial y comenzar a reconocer conjuntos que posteriormente pueden convertirse en categorías, secciones, filtros o relaciones dentro del portafolio.

Categorización

Objetivo: Definir categorías que faciliten la comprensión del contenido.

Descripción: Categorizar implica pasar de agrupaciones exploratorias a conjuntos definidos mediante criterios reconocibles. Una categoría establece una relación entre diferentes contenidos y permite comprender por qué determinados elementos pertenecen al mismo grupo.

Las categorías deben surgir de las características reales del contenido y responder a una necesidad de organización. No todas las características necesitan convertirse en categorías visibles dentro del portafolio.

Una buena categorización permite organizar un sistema sin depender de cada proyecto individual. Las categorías pueden modificarse conforme crece el contenido, pero sus criterios deben ser suficientemente claros para poder decidir dónde pertenece cada nuevo elemento.

Jerarquía

Objetivo: Establecer prioridades y niveles de importancia entre la información.

Descripción: No toda la información tiene el mismo peso. La jerarquía permite distinguir qué elementos necesitan aparecer primero, cuáles proporcionan contexto y cuáles funcionan como información complementaria.

Un proyecto puede contener título, año, descripción, cliente, rol, imágenes, colaboradores, enlaces y procesos, pero no todos estos elementos necesitan mostrarse simultáneamente ni con la misma importancia.

Definir jerarquías antes de diseñar permite separar estructura de información de presentación visual. Primero se determina qué información es principal, secundaria o complementaria; posteriormente el sistema visual encontrará mecanismos para expresar esas diferencias.

Relaciones

Objetivo: Identificar conexiones entre proyectos, categorías y contenidos.

Descripción: La información de un portafolio no tiene que funcionar como una colección de elementos aislados. Los contenidos pueden relacionarse mediante categorías, disciplinas, clientes, técnicas, años, colaboraciones, temas o cualquier otra propiedad compartida.

Reconocer estas relaciones permite comenzar a pensar el portafolio como un sistema. Un mismo proyecto puede conectarse con diferentes contenidos dependiendo de sus características y del tipo de recorrido que se quiera permitir.

Las relaciones también permiten construir sistemas escalables: cuando se incorpora un nuevo proyecto, sus propiedades permiten conectarlo con contenidos existentes sin necesidad de diseñar una estructura completamente nueva.

Estructura de navegación

Objetivo: Diseñar una organización que permita recorrer la información de manera clara.

Descripción: La navegación representa una posible forma de recorrer la estructura de información. Antes de diseñar menús, botones o interfaces es necesario decidir qué contenidos existen, cómo se relacionan y cuáles necesitan convertirse en puntos principales de acceso.

Una estructura de navegación puede incluir secciones como proyectos, información personal, contacto o categorías específicas, pero debe responder al contenido real y al posicionamiento definido previamente.

El objetivo no es agregar la mayor cantidad posible de opciones, sino construir recorridos comprensibles que permitan acceder a la información relevante y entender cómo están organizadas las diferentes partes del portafolio.

Actividades

Estas actividades parten del universo de información y de la selección realizada durante las unidades anteriores. El objetivo será transformar proyectos y materiales diferentes en un sistema de información que pueda crecer y posteriormente convertirse en la estructura del portafolio.

Actividad 1 · Agrupación y categorización

Objetivo

Explorar diferentes maneras de organizar los proyectos para identificar categorías y relaciones significativas.

Instrucciones

Utiliza los proyectos seleccionados para tu portafolio y realiza diferentes agrupaciones.

Prueba al menos tres criterios.

Por ejemplo:

  • Disciplina.
  • Técnica.
  • Tema.
  • Tipo de proyecto.
  • Cliente.
  • Año.
  • Formato.
  • Contexto.
  • Proyecto personal, académico o comercial.
  • Interés o área de práctica.

Un mismo proyecto puede pertenecer a diferentes grupos.

Compara los resultados y responde:

  • ¿Qué agrupaciones ayudan a comprender mejor tu trabajo?
  • ¿Qué categorías contienen suficientes proyectos para resultar útiles?
  • ¿Existen categorías demasiado amplias?
  • ¿Existen categorías demasiado específicas?
  • ¿Qué proyectos podrían pertenecer a más de una categoría?
  • ¿Qué agrupaciones son útiles para ti pero no necesariamente para quien visite el portafolio?
  • ¿Qué categorías podrían seguir funcionando cuando agregues proyectos nuevos?

Entregable

Un documento que incluya:

  1. Los criterios de agrupación utilizados.
  2. Los grupos resultantes.
  3. Las relaciones encontradas.
  4. Una propuesta inicial de categorías para el portafolio.

Actividad 2 · Estructura de un proyecto

Objetivo

Identificar las propiedades que comparten diferentes proyectos para construir una estructura común de información.

Instrucciones

Compara los proyectos.

Identifica:

  • Qué propiedades aparecen siempre.
  • Qué propiedades aparecen solamente algunas veces.
  • Qué información falta.
  • Qué propiedades podrían utilizarse para relacionar proyectos.
  • Qué información es necesaria para comprender un proyecto.
  • Qué información es complementaria.

A partir de esta comparación construye una estructura común capaz de representar diferentes proyectos.

No diseñes todavía una card, página o interfaz. El resultado debe permanecer como información estructurada.

Actividad 3 · Jerarquía y arquitectura

Objetivo

Definir cómo se organizan y relacionan los principales contenidos del portafolio.

Instrucciones

Utiliza las categorías, propiedades y relaciones encontradas en los ejercicios anteriores.

Identifica primero los principales tipos de contenido.

Por ejemplo:

Portafolio

Perfil
Proyectos
Categorías
Información
Contacto

Después establece relaciones entre ellos.

Por ejemplo:

Portafolio
│
├── Perfil
│
├── Proyectos
│   ├── Proyecto
│   ├── Proyecto
│   └── Proyecto
│
├── Categorías
│   ├── Categoría
│   └── Categoría
│
└── Contacto

La estructura debe representar cómo está organizada la información, no cómo se verá visualmente el sitio.

Finalmente identifica:

  • Información principal.
  • Información secundaria.
  • Relaciones entre contenidos.
  • Posibles puntos de navegación.
  • Contenidos que necesitan una vista propia.
  • Contenidos que pueden compartir una misma estructura.

Entregable

Un documento en texto plano que incluya:

  1. Tipos de contenido.
  2. Propiedades principales.
  3. Categorías.
  4. Relaciones.
  5. Jerarquía.
  6. Una representación textual de la arquitectura del portafolio.

Este resultado funcionará como el modelo estructural del contenido. En las siguientes unidades podrá traducirse progresivamente en vistas, componentes y estructuras web sin perder la lógica definida previamente.
